# 数据库迁移规范（sql-migration）

## 何时使用

任务要求新增或修改数据库表结构、写迁移文件时，参考本技能。

## 命名

`NNNN_description.up.sql` / `NNNN_description.down.sql`，编号严格按现有最大编号
递增，不复用、不跳号；一次迁移只做一件事，不要把好几个不相关的表变更塞进同一
个编号里。

## 铁律

1. **每个 up 必须有对应的 down，且 down 必须能把 up 的效果完全撤销**——迁移是
   要能回滚的操作，不是单向脚本。
2. **优先向后兼容**：加列先给默认值或允许 NULL，不要在同一次迁移里既加
   `NOT NULL` 约束又要求对存量数据全量回填——旧代码在迁移应用的瞬间还在跑。
3. **大表加索引用 `CREATE INDEX CONCURRENTLY`**，且不能跟其它 DDL 放在同一个
   事务里（`CONCURRENTLY` 不允许在事务块内执行，很多迁移框架默认把整个文件
   包一层事务，写之前先确认框架的行为）。
4. **迁移脚本里只做 schema 变更，不写业务逻辑**：需要回填数据时，回填脚本与
   schema 变更分成两个独立的迁移文件，方便单独重跑与排查。
5. **删列/删表前先观察一个发布周期**：先在应用代码里停止读写该列，确认没有
   隐藏依赖后才在下一次迁移里真正删除，不要一步做完。
