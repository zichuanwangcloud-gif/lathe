# Go 测试规范（go-testing）

## 何时使用

任务要求给 Go 代码补测试、修复失败测试、或提升覆盖率时，参考本技能里的约定，
不要每次都从零决定风格。

## 核心规范

1. **表驱动测试优先**：用 `[]struct{ name string; ... }` + 循环内
   `t.Run(tt.name, func(t *testing.T) { ... })`，而不是给每个用例单独写一个
   `TestXxx` 函数。
2. **用例名字说清楚"给定什么、断言什么"**：`"空输入返回默认值"` 好于
   `"case1"`；这样测试失败时的输出本身就是文档。
3. **mock 走接口边界**：外部依赖（DB/网络/文件系统）通过接口注入假实现，不在
   普通单测里起真实网络或数据库连接。需要真实依赖的测试要能通过环境变量
   或 `t.Skipf` 优雅跳过，不能让没装依赖的人跑不动 `go test ./...`。
4. **失败信息带上实际值与期望值**：`t.Errorf("got %v, want %v", got, want)`，
   不要只写 `"test failed"`。
5. **先红后绿**：补测试前先确认它在改动前是失败的（证明测试真的在测这件事），
   改完实现后再确认它通过；纯粹为覆盖率堆的、永远通过的测试没有意义。
